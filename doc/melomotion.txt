1. INTRODUCTION                                             *melomotion-intro*

melomotion records the keys you use to move around and where they take you:
motions, jumps, searches, scrolling, switching windows, buffers and tabs, and
opening files through pickers such as Telescope. Moving a visual selection
counts too. Editing is left out: text changes, insert mode and operators
(including yank) are never recorded.

Nothing is recorded until you run |:Melomotion| start, or set `autostart`.
Recordings stay on your machine, see |melomotion-recordings|.

Requires Neovim 0.10 or newer. Run `:checkhealth melomotion` to check.

==============================================================================
2. COMMANDS                                              *melomotion-commands*

                                                                 *:Melomotion*
:Melomotion start       Start a recording session. Each session is one file.
:Melomotion stop        Stop recording and write everything left.
:Melomotion toggle      Start or stop.
:Melomotion save        Write what's recorded so far and keep recording.
:Melomotion status      Show the session file and how much is written.
:Melomotion show        Show the session being recorded, or else the newest
                        one, as lyrics. See |melomotion-lyrics|.
:Melomotion show pick   Choose a session to show, with |vim.ui.select()|.

A running session is also stopped and written when Neovim exits.

==============================================================================
3. MAPPINGS                                              *melomotion-mappings*

melomotion sets no keymaps. Bind these instead:

  <Plug>(melomotion-start)                         *<Plug>(melomotion-start)*
  <Plug>(melomotion-stop)                           *<Plug>(melomotion-stop)*
  <Plug>(melomotion-toggle)                       *<Plug>(melomotion-toggle)*
  <Plug>(melomotion-save)                           *<Plug>(melomotion-save)*
  <Plug>(melomotion-show)                           *<Plug>(melomotion-show)*

Example: >lua
  vim.keymap.set("n", "<leader>mm", "<Plug>(melomotion-toggle)")
<
==============================================================================
4. CONFIGURATION                                           *melomotion-config*

Calling setup() is optional. Options left out keep their defaults: >lua
  require("melomotion").setup({
    autostart = false,
    dir = vim.fn.stdpath("state") .. "/melomotion",
    flush_interval = 60000,
    max_buffered = 500,
    async_window = 2000,
  })
<
  autostart         Start recording when setup() runs.
  dir               Directory for session files. `~` is expanded.
  flush_interval    Milliseconds between writes to disk. 0 writes only on
                    save, stop and exit.
  max_buffered      Write early once this many records are waiting.
  async_window      Milliseconds during which a jump that arrives late, such
                    as an LSP go-to-definition, is still credited to the keys
                    that asked for it.

An unknown option or a value of the wrong type is reported, and the previous
options stay in place.

==============================================================================
5. LUA API                                                    *melomotion-api*

require("melomotion").setup({opts})                       *melomotion.setup()*
    Set options, see |melomotion-config|.

require("melomotion").start()                             *melomotion.start()*
    Start recording. Returns the session file path, or nil and an error.

require("melomotion").stop()                               *melomotion.stop()*
    Stop recording. Returns `{ path, written }`, or nil if nothing was
    recording.

require("melomotion").save()                               *melomotion.save()*
    Write what's waiting. Returns `{ path, written }`, or nil.

require("melomotion").status()                           *melomotion.status()*
    Returns `{ recording, path, written, buffered }`.

require("melomotion").is_recording()               *melomotion.is_recording()*
    Returns true while a session is running.

require("melomotion").sessions()                       *melomotion.sessions()*
    Returns the session files, newest first. The running session is
    included even before anything is written.

require("melomotion").read({path})                         *melomotion.read()*
    Returns a session's records (see |melomotion-recordings|) and its path.
    Without {path}: the running session, or else the newest. Records still
    waiting to be written are included. Returns nil if there are no
    sessions.

==============================================================================
6. RECORDINGS                                          *melomotion-recordings*

Each session is a JSON Lines file in `dir`, named `YYYYMMDD-HHMMSS-<pid>.jsonl`.
Every line has `t` (milliseconds since the Unix epoch) and `kind`.

The first line has kind `start`, with `nvim` (version) and `cwd`. The last has
kind `stop`. Every line in between is a movement, and its kind is the biggest
thing that changed: `tab`, `window`, `buffer`, `cursor` or `scroll`.

Movement fields:
  keys      What you typed, such as `2j`, `<C-W>v` or `<Space>ff`, or the full
            command line for `:` and searches, such as `:42` or `/foo`. Empty
            when nothing you typed caused it.
  mode      `n`, or `v`, `V`, `^V` while moving a visual selection.
  from      Where you were: `{ file, ft, line, col, top }`. `col` counts bytes
  to        from 0. `top` is the first line on screen.
  via       Filetype of the picker or float you went through, if any.
  async     true when the keys were credited to a late jump.

Example (one line, wrapped here): >json
  {"t":1761120000123,"kind":"buffer","keys":"<Space>ff","mode":"n",
   "via":"TelescopePrompt","from":{"file":"/p/readme.md","ft":"markdown",
   "line":1,"col":0,"top":1},"to":{"file":"/p/init.lua","ft":"lua",
   "line":1,"col":0,"top":1}}
<
Buffer text is never stored. File paths are, and so are search patterns and
`:` commands that moved you. Recordings are only written to `dir`.

7. LYRICS                                                  *melomotion-lyrics*

|:Melomotion| show lays a session out as a song sheet. Each place you stayed
is a part of the song, and the keys you moved with are its lyrics: >

  ♫ init.lua (feat. config.lua)
    Thursday 22 Oct 2026 · 09:14 · 3:12

  [Intro: init.lua]
  ♪ j×17 k k k, } } /setup n×4 ♪

  [Verse 1: config.lua]
  ♪ <Space>ff (TelescopePrompt) ~ gg G gg ♪

  [Chorus ×3: init.lua ⇄ config.lua]
  ♪ <C-O>  <C-I> ♪

  [Outro: init.lua]
  ♪ <C-O> ~ j×9 ♫
<
The song is named after the file you moved in most, featuring the runner-up.
Under the title are the day, the start time and how long the session ran.

A new part starts where you started, and again each time you switch tab,
window or buffer. It is labelled with the file you landed in:

  Verse         a file where you moved around
  Chorus        a part you repeated. Back-to-back repeats are sung once,
                with a count, such as `×3`
  Bridge        files you only passed through, in order
  Intro, Outro  the first and last parts

A line of lyrics starts with the keys that took you there, then `~`, then the
keys you moved with. The picker you came through is in parentheses. A pause
of a second or more is a comma, and three seconds or more starts a new line.
Up to three repeats of the same keys are spelled out, and more fold into one
word, such as `j×17`. Movements that nothing you typed caused are left out.

Files are named by file name. Files that share one are shown with their path.

The song opens in a scratch buffer along the bottom, with filetype
`melomotion`. Press `q` to close it.
